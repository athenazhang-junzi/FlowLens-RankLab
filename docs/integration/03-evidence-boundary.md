# FlowLens RankLab｜证据与声明边界 v1

## 1. 本阶段结论

Gate A 已完成产品定义、目标架构和事件契约；Gate B 已完成 Metarank 的导入、训练、服务和重排请求；Gate C 已完成统一验证 cohort 评估与 LiveLab 离线摘要导入。本轮验证结果明确不支持“效果提升”，决策为 `ITERATE_AND_RETEST`。

## 2. 继续沿用的证据等级

| 等级 | 定义 | RankLab 示例 | 允许表述 |
|---|---|---|---|
| E1 | 公开数据直接字段或可复算聚合 | `is_click`、`long_view`、内容作者／标签 | “日志字段记录为……” |
| E2 | 由明确规则产生的代理或工程事实 | 命名空间 ID、候选守恒校验、派生新鲜度 | “按 v0.1 规则计算……” |
| E3 | 时间切分的离线训练、回放和比较 | Metarank 与现有基线的统一候选评估 | “离线估计显示……” |
| E4 | 固定种子模拟或人工参数场景 | LiveLab 模拟流量与实验异常 | “模拟结果／演示阈值……” |
| E0 | 设计或待验证假设 | 未来真实请求、线上 A/B、业务收益 | “计划验证／待接入……” |

## 4. 后续运行的最低证据要求

一个 Metarank 集成结果只有同时满足以下条件，才能进入 README、作品集或 LiveLab：

1. `integration_run_id` 唯一，状态为 `VALID`；
2. 输入来自已通过质量门的数据视图；
3. 数据切分、候选政策和标签与基线一致；
4. 事件合同阻断规则全部通过；
5. 模型配置、镜像、哈希、种子和 FlowLens commit 可追溯；
6. API 输入输出候选守恒；
7. 指标由脚本重算并通过独立校验；
8. 报告同时给出点估计、不确定性、护栏和限制；
9. 任何失败或排除样本均有原因和数量；
10. 没有将 E3／E4 表述为线上因果收益。

## 5. 允许与禁止的表达

### Gate A／B／C 当前允许

- “设计了 FlowLens 与 Metarank 的事件契约和可复现集成架构。”
- “将 FlowLens 定位为诊断与评估层，Metarank 定位为可替换的学习排序运行时。”
- “定义了候选守恒、时间顺序、ID 关联和证据等级等阻断规则。”
- “在固定 Metarank 0.8.0 镜像上跑通了导入、训练、服务和重排请求。”
- “50 个验证请求返回 253 个候选，候选守恒通过。”
- “在 2,000 个稳定抽样验证请求上，Metarank 的 NDCG@5 比冻结基线低 0.049803，因此决策为迭代重测。”
- “LiveLab 读取的是 E3 离线回放摘要，不是线上 A/B 看板。”

### Gate A／B 当前禁止

- “Metarank 提升了 NDCG／有效消费。”
- “接入了真实线上流量或执行了 A/B 测试。”
- “FlowLens 自研了 Metarank 的核心算法。”

### Gate B／C 运行后仍需谨慎

- 若点估计为正但区间跨 0：写“点估计为正，区间跨 0，继续重测”，不能写“实现提升”。
- 若标准日志与随机日志排序不一致：写“结果对采集策略敏感”，不能选取有利样本单独宣传。
- 若只在 logged-exposure 候选上评估：写“已记录曝光内的重排”，不能写“全量推荐效果”。
- 若 LiveLab 读取离线产物：写“离线运行摘要”，不能把页面外观称为线上实验系统。
