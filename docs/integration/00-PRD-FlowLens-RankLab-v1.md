## 1. 一句话定位

FlowLens RankLab 是一个面向内容分发策略的可复现离线排序与实验决策工作台：它把 **日志诊断、候选重排、多目标评估和实验准备** 串成一条可核验链路。

它不是推荐平台的完整替代品，也不是 Metarank 的二次开发发行版。FlowLens 提供问题定义、数据门禁、候选与评估；Metarank 提供可替换的学习排序运行时；LiveLab 提供实验健康检查与决策表达。

## 2. 用户问题

当前 FlowLens 已经能回答“日志里有什么问题、策略离线表现如何”，LiveLab 能演示“实验是否健康”，但中间缺少一条可运行的模型服务链：

1. FlowLens 的候选、特征和反馈如何转换为标准排序事件？
2. 一个外部学习排序服务如何训练并返回可解释的重排结果？
3. 新模型结果如何回到同一套有效消费、负反馈、覆盖和重复护栏中比较？
4. 哪些结果是实际运行得到的，哪些只是模拟或未来线上方案？

合并后的产品以这四个问题为主线，而不是以“部署了多少组件”为目标。

## 3. 目标用户与核心任务

### 3.1 目标用户

- 推荐／内容分发策略产品经理：从异常和取舍出发形成策略决策。
- 数据分析师：核对样本、口径、时间切分和不确定性。
- 算法／工程协作者：读取稳定的事件、特征、模型和验收合同。
- 作品集审阅者：沿 Run ID 复核“问题—策略—结果—限制”。

### 3.2 核心任务

1. 从已通过质量门的公开日志生成 Metarank 可接收的内容、排序和交互事件。
2. 使用冻结配置训练一个学习排序基线，并记录版本、参数和训练产物。
3. 将同一候选集发送到排序 API，保存原始顺序、模型顺序、分数和解释特征。
4. 使用 FlowLens 的统一口径比较现有基线、S0–S4 与 Metarank 结果。
5. 只有健康检查和证据门槛满足时，才生成“进入未来实验候选”；否则输出重测或停止。

## 4. 产品闭环

```text
公开行为日志
  → FlowLens 数据质量与时间门禁
  → 供需／消费／重复／负反馈诊断
  → 构造 logged-exposure 候选与事件
  → Metarank 训练和重排
  → FlowLens 多目标离线评估
  → LiveLab 实验健康与决策展示
  → 可追溯证据包
```

## 5. 组件分工

| 组件 | 负责 | 不负责 |
|---|---|---|
| FlowLens Analysis | 数据审计、时间切分、基线候选、标签、离线指标、护栏、决策门 | 不冒充线上服务，不把已记录曝光当全量召回 |
| Metarank Runtime | 接收事件、构建特征、训练 LambdaMART、对显式候选进行重排 | 不决定业务目标，不自动证明线上收益 |
| Integration Adapters | 字段映射、ID 生成、顺序与时间校验、API 调用、运行清单 | 不静默补值，不把缺失字段包装成真实观测 |
| LiveLab | 展示模拟实验诊断，并以独立卡片读取 Gate C 离线摘要 | 不代表真实实验平台，不执行生产流量操作 |
| `metarank-zh` | 提供独立的中文学习资料和上游说明 | 不进入 FlowLens 自有代码归属，不作为运行时 fork |

## 6. MVP 范围

### 6.1 Gate B 必做

- 用小型契约样例验证 `item → ranking → interaction` 导入。
- 固定 Metarank 版本、配置、随机种子与运行命令。
- 从 FlowLens 训练窗生成离线回放事件，训练一个可重现的模型。
- 从验证／测试候选生成 `/rank/<model>` 请求，保存响应和失败记录。
- 对事件数、唯一 ID、父子关联、时间顺序、候选守恒执行阻断校验。
- 生成独立 Run ID 和 manifest；失败运行不得进入评估页。

### 6.2 Gate C 必做

- 将 Metarank 分数作为新基线写入 FlowLens 评估输入，不覆盖已有结果。
- 复用 NDCG@5、Top-5 ECR、覆盖、作者／标签重复和负反馈护栏。
- 输出配对差异与区间；若区间或护栏不满足，保留 `ITERATE_AND_RETEST`。
- LiveLab 读取导出的真实离线运行摘要，同时保留醒目的“离线运行”标签。
- LiveLab 的模拟 A/B 与 FlowLens 的实际离线运行在数据层和文案层分开。

### 6.3 Gate D 必做

- 一条文档化命令完成契约样例的导出、训练、重排、评估和校验。
- 记录 Docker 镜像版本／摘要、FlowLens commit、配置哈希和随机种子。
- 完成许可证选择、第三方声明、数据许可和公开发布检查。
- 在干净环境中复现，不依赖本机绝对路径或未提交数据。

## 7. 非目标

- 不复制或修改 Metarank 的 Scala 核心源码。
- 不实现全量内容召回、实时特征平台、亿级流量或生产高可用。
- 不把 KuaiRand-Pure 的离线日志解释为腾讯视频或任何真实业务平台数据。
- 不把按用户／日期构造的回放候选称为原始线上请求或真实曝光列表。
- 不把 LiveLab 的固定种子模拟称为已经执行的线上 A/B。
- 不预设 Metarank 一定优于现有 MultiTaskHashSGD、ItemCF 或策略重排。
- 不为追求“正向结果”修改测试窗、标签、候选或门槛。

## 8. 成功标准

成功不以某个模型必须提升为条件，而以链路是否可信为条件：

| 维度 | Gate B／C 验收 |
|---|---|
| 可运行 | 契约样例和一条公开数据离线链路能够完成 |
| 可复现 | 相同输入、配置、镜像和种子产生一致的结构化产物 |
| 可追溯 | 排序结果能追溯到数据版本、候选、模型、特征和请求 |
| 可比较 | Metarank 与原基线使用同一候选、标签、切分和指标口径 |
| 可解释 | 至少保留上游分数、模型分数、最终位置和可用特征解释 |
| 守边界 | 页面、README 和报告明确标注 E1–E4，不产生线上收益表述 |

## 9. 版本与仓库策略

- 主仓库：在 FlowLens 中增加 `scripts/` 适配器、`services/metarank/`、`config/integration/`、`reports/integration/`、`apps/livelab/` 与本地 `runs/`。
- 运行时：第一版以官方 `metarank/metarank:0.8.0` 为文档基线，Gate B 需进一步固定镜像摘要。
- 中文资料：`metarank-zh` 独立维护，只通过链接引用。
- LiveLab：Gate D 纳入主仓库，由 FlowLens 生成静态摘要；前端不直接依赖 Metarank 服务。
- 许可证：FlowLens 主仓库代码采用 Apache License 2.0；KuaiRand-Pure 和 Metarank 继续遵循各自许可与归属声明。

## 10. 开放问题

1. FlowLens 最终采用 Apache-2.0、MIT，还是保留全权利；仓库所有者需在 Gate D 前决定。
2. 负反馈是否进入 Metarank 训练权重，必须先验证目标版本对权重语义的支持；在此之前只作为 FlowLens 护栏。
3. LiveLab 已选择直接读取静态导出；如果未来需要连续多运行对比，再评估是否增加轻量本地 API。
4. 若 Metarank 模型无法在当前公开日志结构上稳定训练，应保留失败报告，不能改写为成功集成。
